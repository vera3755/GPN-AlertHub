# GPN AlertHub

Прототип middleware для обработки событий мониторинга, интеллектуальной нормализации, дедупликации, корреляции инцидентов и маршрутизации уведомлений.

## Быстрый запуск

### Требования

- Python 3
- Windows 10/11 для запуска через `run.bat`
- Дополнительные Python-библиотеки не требуются

### Вариант 1 — Windows

1. Скачайте или клонируйте репозиторий.
2. Запустите `run.bat`.
3. Браузер должен открыться автоматически.
4. Если браузер не открылся, перейдите вручную по адресу:

```text
http://127.0.0.1:8767
```

### Вариант 2 — запуск из терминала

```bash
python server.py
```

Если команда `python` недоступна в Windows, используйте:

```bash
py server.py
```

После запуска в консоли появится адрес веб-интерфейса.

## Быстрая проверка решения

1. Откройте раздел **«Генератор событий»**.
2. Запустите сценарий **`P0: SW-17 → DB-17 → БУ-17`**.
3. Перейдите в **«AI / Инциденты»**.
4. Система должна показать:
   - 3 входящих события;
   - 1 объединённый инцидент;
   - критичность `P0`;
   - вероятную первопричину `SW-17`;
   - этапы `NORMALIZED → CORRELATED → ROUTED`.
5. Откройте **«TrueConf (эмулятор)»** и проверьте доставку уведомлений.
6. Нажмите **«Принять в работу»**.
7. В разделе **«Мои подписки»** можно изменить подписки пользователя и повторить генерацию события.
8. В **«Дашборде»** отображаются показатели обработки событий.

Роль пользователя задаётся централизованно и не изменяется самим пользователем. Подписки управляются отдельно от прав доступа.

## Что эмулируется в прототипе

- события Zabbix / SolarWinds / Prometheus создаются встроенным генератором;
- LDAP/AD и CMDB представлены локальными демонстрационными справочниками;
- вместо реального API TrueConf пока используется Mock-провайдер.

Основной pipeline работает локально end-to-end: событие → классификация → дедупликация → корреляция → инцидент → Rule Engine → маршрутизация → доставка → подтверждение → аудит.

## Автоматические тесты

В проекте есть **unit-тесты** и **integration-тесты**. Используется стандартный модуль `unittest`, поэтому устанавливать дополнительные библиотеки не нужно.

### Запуск всех тестов на Windows

Запустите:

```text
run_tests.bat
```

### Запуск из терминала

```bash
python -m unittest -v test_unit.py test_integration.py
```

или в Windows:

```bash
py -m unittest -v test_unit.py test_integration.py
```

### Unit-тесты проверяют

- токенизацию и нормализацию синонимов;
- ML-классификацию событий;
- TF-IDF / cosine similarity;
- выбор получателей по подпискам и критичности.

### Integration-тесты проверяют

- полный pipeline `event → incident → routing → delivery`;
- подавление дублирующих событий;
- P0-каскад `SW-17 → DB-17 → БУ-17`;
- P2-маршрутизацию события `DC-01`;
- HTTP API `/api/generate` и `/api/state`.

Тесты используют отдельную временную SQLite-базу и **не изменяют** демонстрационную `alerthub_v2.db`.

## Файлы репозитория

```text
server.py             основной код приложения
run.bat               запуск приложения на Windows
test_unit.py          unit-тесты
test_integration.py   integration-тесты
run_tests.bat         запуск всех тестов на Windows
README.md              инструкция по запуску и тестированию
.gitignore             исключает локальную БД и временные файлы
```

Файл `alerthub_v2.db` не хранится в репозитории: приложение создаёт его автоматически при первом запуске.
